# Contributing

## Development rules

1. Create a separate branch for every feature or fix.
2. Keep commits small and focused.
3. Do not commit secrets or confidential data.
4. Add or update tests when changing application logic.
5. Run tests before opening a pull request.
6. Update documentation when project behavior changes.

## Branch naming

Use one of the following prefixes:

- `feat/` for new functionality
- `fix/` for bug fixes
- `docs/` for documentation
- `test/` for tests
- `refactor/` for internal code improvements

Examples:

```text
feat/add-gtfs-import
fix/prevent-duplicate-records
docs/update-local-setup
```

## Commit messages

Use short messages describing the completed change.

Examples:

```text
Add initial project structure
Add PostgreSQL development container
Fix duplicate ingestion records
```
